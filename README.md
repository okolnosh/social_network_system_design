# Социальная сеть для путешественников
Домашнее задание в рамках курса [System Design](https://balun.courses/courses/system_design) по проектированию социальной сети для путешественников
# Функциональные требования
- публикация постов из путешествий с фотографиями, небольшим описанием и привязкой к конкретному месту путешествия;
- оценка и комментарии постов других путешественников;
- подписка на других путешественников, чтобы следить за их активностью;
- поиск популярных мест для путешествий и просмотр постов с этих мест;
- просмотр ленты других путешественников и ленты пользователя, основанной на подписках в обратном хронологическом порядке;
# Нефункциональные требования
- DAU: 10 000 000 через год и будет расти линейно.
- Доступность: 99,99%
- Регион использования: пользователи из стран СНГ
- Сезонность: в летний период может быть повышенная нагрузка из-за сезона отпусков (в полтора раза)
- Хранение данных: хранятся всегда (без ограничения по сроку хранения).
- Фотографии при загрузке должны сжиматься (вес не более 2 МБ).
- Время загрузки ленты (20 постов в хронологическом порядке): не более 1 секунды
- Время создания поста с фото (сжатие + загрузка на сервер): не более 3 секунд
- Время загрузки профиля (с 20 постами): не более 1 секунды
- Время загрузки комментариев к посту: не более 1 секунды
- Время отправки комментария: не более 1 секунды
- Время установки/снятия лайка: не более 500 мс

Ограничения:
1. Количество возможных подписчиков у пользователя: 1 000 000
2. Количество возможных подписок у пользователя: 1 000 000 
3. Количество постов/лайков/комменариев: не ограничено

# Действия пользователей с ожидаемым RPS
1. Просмотр ленты (загрузка 10 постов при обновлении/скроллинге ленты, в среднем каждый пользователь обновляет ленту 10 раз в день), read: DAU * 10 / 86400 = 10 000 000 * 10 / 86400 ≈ 1157 RPS
2. Поставить/снять лайк, write: 1000 RPS
3. Просмотр профиля (загрузка по 10 постов, в среднем каждый пользователь открывает профиль 5 раз в день), read: DAU * 5 / 86400 = 10 000 000 * 5 / 86400 ≈ 579 RPS
4. Просмотр комментариев к посту, read: 1000 RPS
5. Комментирование поста, write: 500 RPS
6. Публикация поста с фотографией (в среднем каждый пользователь публикует 1 пост в день), write: DAU * 1 / 86400 = 10 000 000 * 1 / 86400 ≈ 116 RPS

## RPS по подсистемам
### Подсистема постов
~~~
RPS read = Просмотр ленты + просмотр профиля = 1157 + 579 = 1736
RPS write = Публикация поста = 116
Медиатрафик (read) = (RPS read * Количество постов * (Количество фотографий (max)* вес фото )) = 1736 * 10 * (5 * 2 мб) = 173 600 мб/c ~ 170 гб/c
~~~
### Подсистема реакций
~~~
RPS read = Просмотр комментариев к посту = 1000
RPS write = Комментирование + установка/снятие лайка = 500 + 1000 = 1500
~~~
### Подсистема обработки публикаций
- сжатие фото;
- генерация превью
- сохранения в медиа-хранилище;
- генерация превью
~~~
RPS write = Публикация поста = 116
Медиатрафик (write): 116 * 10 мб = 1160 мб/с ≈ 1.13 гб/с
~~~

## Суммарный трафик
### Read
~~~raw
Трафик read = (RPS просмотр ленты * размер ленты) + (RPS просмотр профиля * размер профиля) + (RPS просмотр комментариев к посту * размер запроса комментариев) = (1157 * 100 мб) + (579 * 100 мб) + (1000 * 3.6 мб) = 177 200 мб/с ≈ 173 гб/с
~~~

### Write
~~~raw
Трафик write = (Установка/снятие лайков * размер запроса на установку/cнятие лайка) + (Добавление комментария * размер запроса  добавления комментария) + (Публикация поста * размер поста) = (1000 * 52 б) + (500 * 352 байта) + (116 * 10мб) = 1 216 576 160 б/c ≈ 1160 мб/c ≈ 1.13 гб/c
~~~

# Расчёт дискового пространства за год
Считаются данные в разрезе года.
Допущение: 1 ТБ = 1000 ГБ = 1 000 000 МБ

## Подсистема постов
Хранит метаданные постов (таблица `publications`); сами фото — в подсистеме обработки публикаций.
~~~raw
Размер строки = описание 500 + id 16 + гео (2*8) + timestamp 20 + счётчики (8+8) + имя 30 ≈ 600 байт
Постов в год = DAU * 1 пост/день * 365 = 10 000 000 * 365 = 3 650 000 000
capacity = 3 650 000 000 * 600 байт = 2 190 000 000 000 байт ≈ 2,2 ТБ/год

RPS:
  read  = просмотр ленты 1157 + просмотр профиля 579 = 1736
  write = публикация поста 116
traffic_per_second = (1736 + 116) * 600 байт = 1852 * 600 = 1 111 200 байт ≈ 1,05 МБ/с
iops = 1736 + 116 = 1852
~~~
Расчёт количества дисков:
~~~raw
HDD:
  capacity = 2,2 ТБ / 32 ТБ = 0,07 
  throughput = 1,7 МБ/с / 100 МБ/с = 0,02 
  iops = 1852 / 100 = 18,52
  Disks = max(1, 1, 28) = 19 дисков

SSD SATA:
  capacity = 2,2 / 100 ТБ = 0,02
  throughput = 1,7 / 500 ≈ 0
  iops = 1852 / 1000 = 1,85
  Disks = max(1, 1, 3) = 2 диска

SSD nVME:
  capacity = 2,2 / 30 = 0,07
  throughput = 1,7 / 3000 ≈ 0
  iops = 1852 / 10000 = 0,18
  Disks = max(1, 1, 1) = 1 диск
~~~
Итог: выбираем 2 ssd sata диска по 6 ТБ, т.к. это дешевле, чем 1 ssd nvme

## Подсистема реакций

## Подсистема обработки публикаций
Хранит медиа (фотографии + превью) в объектном хранилище.
~~~raw
Постов в день = DAU * 1 пост/день = 10 000 000
Объём за год — по среднему RPS публикаций:
  Фотографии (≤5 шт * 2 МБ = 10 МБ на пост):
    В год = 10 000 000 * 10 МБ * 365 = 36 500 000 000 МБ = 36 500 ТБ ≈ 36,5 ПБ/год
  Превью (5 шт * ~150 КБ ≈ 0,75 МБ на пост):
    В год = 10 000 000 * 0,75 МБ * 365 = 2 737 500 000 МБ ≈ 2 738 ТБ ≈ 2,7 ПБ/год
capacity = 36 500 + 2 738 = 39 238 ТБ ≈ 39,2 ПБ/год

RPS:
  read медиа = просмотр ленты 1157 + просмотр профиля 579 = 1736
  объектов на запрос = 10 постов * 5 фото = 50
traffic_per_second = медиатрафик чтения = 1736 * 10 * (5 * 2 МБ) = 173 600 МБ/с ≈ 170 ГБ/с
iops = 1736 * 50 = 86 800 ≈ 87 000
~~~
Расчёт количества дисков:
~~~raw
HDD:
  capacity = 39 238 ТБ / 32 ТБ = 1226,2
  throughput = 173 600 МБ/с / 100 МБ/с = 1736
  iops = 86 800 / 100 = 868
  Disks = max(1227, 1736, 868) = 1736 дисков

SSD SATA:
  capacity = 39 238 / 100 = 392,4
  throughput = 173 600 / 500 = 347,2
  iops = 86 800 / 1000 = 86,8
  Disks = max(393, 348, 87) = 393 диска

SSD nVME:
  capacity = 39 238 / 30 = 1307,9
  throughput = 173 600 / 3000 = 57,9
  iops = 86 800 / 10000 = 8,68
  Disks = max(1308, 58, 9) = 1308 дисков
~~~
Итог: выбираем 393 ssd sata диска по 100 ТБ, т.к. это дешевле, всё остальное
